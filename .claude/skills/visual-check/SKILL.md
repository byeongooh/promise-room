# 화면 확인

빌드가 통과했다는 것과 화면이 제대로 보인다는 것은 다른 말이다.
이 프로젝트에서 실제로 갈렸던 것들만 적는다.

## 1. 개발 서버는 preview_start로 띄운다

Bash로 `npm run dev`를 돌리지 않는다. preview_start가 띄운 서버라야
스크린샷·콘솔·네트워크를 같이 읽을 수 있다.

```
preview_start({ name: "promise-room-dev" })
navigate({ url: "http://localhost:3000/login", tabId: "seed" })
```

## 2. 스크린샷보다 값을 읽는 게 정확할 때가 많다

**작은 차이는 눈으로 안 갈린다.** 사과 꼭지 굵기를 크기별로 바꾼 적이 있는데,
스크린샷으로는 1px 차이를 확인할 방법이 없었다. 대신 렌더된 값을 직접 읽었다.

```
javascript_tool → document.querySelectorAll('svg') 를 훑어
                  stroke-width / ellipse 개수를 뽑아 본다
```

결과가 `200px → 꼭지 6·광 1개`, `26px → 꼭지 10·광 0개`로 나와서
크기 규칙이 실제로 도는 것을 확인했다. 이런 검증은 스크린샷보다 강하다 —
숫자로 남고, 다음에 회귀했는지도 같은 방법으로 본다.

**규칙이 조건에 따라 갈리는 것**(크기·상태·날짜)은 전부 이렇게 확인한다.

## 3. 스크린샷은 브라우저 패널이 화면에 떠 있어야 찍힌다

안 떠 있으면 이 오류가 난다.

```
the Browser pane is not displayed, so the page is not compositing frames
```

페이지가 프레임을 안 그려서 생기는 것이라 재시도해도 소용없다.
사용자에게 패널을 띄워 달라고 하거나, 위 2번처럼 값으로 확인한다.

## 4. 로그인이 필요한 화면 — 여기가 이 프로젝트의 진짜 벽이다

로그인 화면(`/login`)과 비밀번호 화면 말고는 **전부 카카오 로그인이 필요하다.**
플랜 상세·대시보드·내 사과가 다 여기 걸린다. 자동화로는 카카오 로그인을
통과할 수 없다(그래야 맞다).

여는 방법은 둘 중 하나다. 둘 다 **사람이 한 번 직접 로그인**해야 한다.

| 방법 | 어떻게 |
|---|---|
| Claude in Chrome 확장 | 이미 로그인돼 있는 실제 Chrome에 붙는다. 확장을 깔고 연결하면 그 세션을 그대로 쓴다 |
| Playwright | 브라우저 프로필을 저장해두고 재사용한다. 한 번 로그인해 프로필을 남기면 그다음부터 열린다 |

**둘 다 안 되면 "화면은 확인하지 못했다"고 명시한다.** 빌드 통과를 화면
확인으로 바꿔 말하지 않는다.

## 5. 무엇을 보려면 무엇을 만들어야 하는가

플랜 상세는 **상태에 따라 화면이 통째로 갈린다.** 아무 플랜이나 열어서는
보려는 칸이 안 나온다. 판단은 전부 `lib/plan-phase.ts`에 있다.

| 보려는 것 | 필요한 상태 |
|---|---|
| 날짜 투표 · 장소 비교 · 제안 목록 | **정하는 중**(확정 전) |
| 내 도착 시각 · 가기 어려울 때 · 날짜 바꾸기 | **확정됨**(방장이 확정을 누른 뒤) |
| 출발지 칸(OriginPicker) | 장소 **미정** |
| 지도 · 경로 · 나가야 하는 시각 | 장소에 **좌표가 있음** |
| 온라인 링크 카드 | `meetingMode: "online"` |
| 확인/가는 중/도착 버튼 | **약속 당일**(그 전에는 자리만 있고 안내 문구가 뜬다) |

## 6. 당일 알림은 평소에 안 뜬다 — 시각을 맞춰야 본다

아침 알림과 출발 알림은 **날짜·시각 조건에 걸려 있어서** 아무 때나 열어서는
절대 안 보인다. `planNudge()`가 이렇게 가른다.

```
확정된 플랜 + 약속 당일
  09:00 ~ 약속 1시간 전   → morning  (도착 시각을 아직 안 적었을 때만)
  약속 1시간 전 ~ +30분   → onway    (상태가 아직 '확인 안 함'일 때만)
  그 밖                   → 안 뜸
```

보려면 **약속 날짜를 오늘로, 시각을 지금부터 1~2시간 뒤로** 잡은 플랜을 하나
만든다. 그러면 아침 알림이 뜬다. 출발 알림을 보려면 약속 시각을 지금부터
30분 뒤로 잡는다.

한 번 닫으면 그날은 다시 안 뜬다(localStorage에 기억한다). 다시 보려면
`applan:nudge:`로 시작하는 키를 지운다.

```
javascript_tool → Object.keys(localStorage)
                    .filter(k => k.startsWith('applan:nudge:'))
                    .forEach(k => localStorage.removeItem(k))
```

## 7. 라이트·다크를 같이 본다

색은 전부 CSS 변수로 두 벌이 있다(`app/globals.css`). 한쪽만 보고 넘어가면
다른 쪽에서 대비가 무너져 있는 것을 놓친다.

```
resize_window({ colorScheme: "dark" })
```

특히 흰색을 직접 쓴 자리를 조심한다. 사과의 광은 `--tk-paper`가 아니라 흰색
고정인데, paper는 다크에서 검정이라 광이 아니라 그늘이 되기 때문이다.
이런 자리는 다크에서 직접 봐야 안다.

## 말할 때

- **본 것과 못 본 것을 나눈다.** "빌드는 통과했지만 로그인이 필요한 화면은
  못 봤다"처럼 범위를 밝힌다.
- 값으로 확인했으면 그 값을 그대로 적는다. "잘 나온다"보다
  "200px에서 꼭지 6, 26px에서 꼭지 10으로 확인했다"가 낫다.
